## P1 — 让一个人真的能天天用（1–2 周，按依赖排序）

| # | 事项 | 为什么现在 | 依赖 | 估时 |
| --- | --- | --- | --- | --- |
| P1-1 | **鉴权与单用户 token** | 现在任何能连到端口的人都能停工单、改策略 | 无 | 0.5 天 |
| P1-2 | **策略规则的可视化编辑** | 现在只能改 `mode`/`watchdog`；阈值与 scope 还得改代码 | P1-1 | 1.5 天 |
| P1-3 | **批次活动数据导入（CSV/表单）** | 现在活动数据是种子；真实核算要能录入 kWh/水/肥/运费 | 无 | 1 天 |
| P1-4 | **真实 IoT Source（MQTT/HTTP 上报）** | 模拟器证明链路，真实农场要 ESP32 → broker → intake | P1-1 | 2 天 |
| P1-5 | **因子库替换为可核证来源** | 当前因子全部 `unverified`，不能对外 | 采购/授权（外部依赖） | 2–3 天 + 数据授权 |
| P1-6 | **导出：批次 PDF 一页纸 + Zenodo 包** | 审阅者要能离线复核；发布需要 DOI | P1-3、P1-5 | 1.5 天 |
| P1-7 | **工单目录的只读浏览 + 下载 zip** | 现在只能逐个看文件 | 无 | 0.5 天 |
| P1-8 | **飞书卡片消息 + 文件上传**（文本已交付） | 现在结果只能以文本回群，产物要回面板取 | P0-10 | 1 天 |
| P1-9 | **其他出口：邮件 / 通用 webhook** | 不是每个团队都在飞书里 | P1-1 | 1 天 |

**P1 的验收线**：`真实批次数据 → 工单 → 账本 → 一页 PDF`，中间没有任何一步需要人看日志或改数据库。

## 明确不做

| 不做 | 原因 |
| --- | --- |
| 自建 LLM 推理服务 | 不是本系统的护城河；`DSH_LLM_URL` 兼容任何 OpenAI 风格端点 |
| 通用 Agent 框架 | DeepSeek 已经开源了；本仓库只做"咖啡×碳"的落地形态 |
| 自动对外发布碳声明 | 因子未核证；发表前必须过 P2-2 的闸门 |
| 区块链 | 单机哈希链已足够审计；链上锚定是 P2 的可选项，不是前提 |

## 风险表（按"会不会毁掉可信度"排序）

| 风险 | 触发条件 | 现在怎么挡 |
| --- | --- | --- |
| 未核证因子被当成结论引用 | 有人只截图 Ledger 面板 | 每份 doc 带 `warnings`；Dossier 页红框；README 首段声明 |
| Worker 范围越权 | 规则 scope 写宽了 | `ToolBox._check` 拒绝并留痕 |
| 卡死被误判为"在干活" | 无心跳 | Watchdog 90s 硬判据，3 次后升给人 |
| 哈希链被"修好" | 有人直接改库 | `verify()` 每次面板渲染都跑；篡改即红 |
| 重启丢工作 | 笔记本没电 | 状态全在 SQLite；pending 重发、running 中断重试 |
| 伪造飞书回调 | webhook 地址泄露 | 验签（有 Encrypt Key 时）+ 每个回调校验 Verification Token + Source 白名单 |
| 演示数字被当成实测 | 有人看到 EC 曲线 | 面板 `simulated` 徽章 + 文档写明 |
